# 월드 구역과 방문 상태

## 목표

하나의 `Main` Graybox를 백트래킹 샤프트, 시작 홀, 이동 실험실의 세 구역으로
명시하고, 플레이어가 발견한 구역을 영구 ID로 기록한다. 현재는 한 Scene에서
동작하지만 이후 Additive Scene 로딩, 지도와 세이브가 같은 구역 정의를
재사용하도록 경계를 먼저 세운다.

## 구역 구성

| ID | 표시 이름 | X 범위 | 현재 역할 |
|---|---|---:|---|
| `backtrack_shaft` | 백트래킹 샤프트 | -13.0 ~ -8.5 | 벽 잡기 해금 후 오르는 수직 보상 동선 |
| `start_hall` | 시작 홀 | -8.5 ~ 6.5 | 시작점·체크포인트·첫 능력 단서 |
| `traversal_lab` | 이동 실험실 | 6.5 ~ 24.5 | 계단·높은 발판·후속 능력 획득 |

세 `WorldZoneVolume`은 경계가 겹치지 않고 맞닿도록 배치했다. Collider는
Trigger이므로 이동을 막지 않으며, 실제 지형 Collider와 별개의 의미 경계로
동작한다. 최초 방문 ID는 한 번만 기록하고, 다른 구역을 거친 재진입은
`ZoneEntered` 이벤트를 다시 발행해 Scene 스트리밍을 갱신한다.

## 구현 후보 비교

| 방식 | 장점 | 단점 | 적합한 상황 |
|---|---|---|---|
| Scene 이름을 구역 ID로 사용 | 추가 데이터가 거의 없음 | Scene 분할 방식이 저장 형식이 됨 | 구조가 절대 바뀌지 않는 작은 데모 |
| Trigger에 문자열 직접 입력 | 빠르게 배치 가능 | 지도·저장·로더에서 문자열이 중복됨 | 일회성 Graybox |
| ScriptableObject 정의 + 방문 ID 집합 | 여러 시스템이 같은 정의 공유, Scene 분할과 저장 분리 | ID 중복 제작 검증 필요 | 구역 스트리밍과 영구 진행이 있는 프로젝트 |

## 선택한 구조

```text
WorldZoneDefinition
        ↓
WorldZoneVolume ── 진입 ──> PlayerWorldState
                              ↓
                       지도 / SaveData / 로더
```

- `WorldZoneDefinition`: 영구 ID, 표시 이름과 설명
- `WorldZoneVolume`: 물리적 진입을 방문 요청으로 변환
- `PlayerWorldState`: 방문 ID `HashSet`과 최초 방문 이벤트

ScriptableObject에는 방문 여부를 저장하지 않는다. 에셋은 모든 플레이어와
테스트가 공유하기 때문에 런타임 상태를 넣으면 Play Mode 종료 후 상태가 섞일
수 있다. 플레이어 상태는 ID만 소유하므로 다음 단계에서 JSON 저장 데이터로
옮기기도 쉽다.

## 수동 시연 방법

1. `Main` 씬을 Play한다.
2. 시작 위치에서 Console의 `구역 진입: 시작 홀` 로그를 확인한다.
3. 오른쪽 계단 구역으로 이동해 `구역 진입: 이동 실험실` 로그를 확인한다.
4. 벽 잡기를 획득한 뒤 시작점 왼쪽 샤프트로 돌아간다.
5. 같은 구역 안에서는 로그가 중복되지 않고, 다른 구역에서 돌아오면 재진입
   로그가 출력되는지 확인한다.
