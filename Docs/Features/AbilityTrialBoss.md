# 세 이동 능력을 시험하는 첫 보스

## 목표

M5의 마지막 단계로, 탐험에서 획득한 2단 점프·공중 대시·벽 잡기가 전투에서도
의미를 갖는지 검증한다. 보스는 단순히 체력이 많은 일반 적이 아니라 서로 다른
대응을 요구하는 세 패턴을 정해진 순서로 순환한다.

## 조우 조건과 배치

`Boss_AbilityWarden`은 이동 실험실 오른쪽 `x=34.5`의 전용 아레나에 배치했다.
다음 세 능력을 모두 획득하기 전에는 회색 대기 상태로 남고 공격하지 않는다.

- `double_jump`
- `air_dash`
- `wall_traversal`

아레나는 `x=26~38` 범위의 바닥, `x=29`의 벽 잡기 기둥, `x=38`의 외곽
벽으로 구성했다. 플레이어는 세 번째 능력 픽업 뒤 기둥을 넘어 보스에게
접근한다. 이동 실험실의 구역 Trigger와 카메라 X 경계도 아레나까지 확장했다.

## 현재 설정

| 항목 | 값 | 의도 |
|---|---:|---|
| 활성 거리 | `5.5m` | 기둥을 넘은 뒤 전투 시작 |
| 허용 높이 차 | `4.5m` | 기둥 위 플레이어도 인식 |
| 1페이즈 선딜 | `0.9초` | 패턴 색과 형태를 읽을 시간 |
| 2페이즈 선딜 | `0.68초` | 체력 절반 이하에서 압박 증가 |
| 공격 후딜 | `1.15초` | 회피 후 반격 기회 |
| 투사체 속도·수명 | `6.5m/s / 3초` | 아레나 안에서 읽을 수 있는 속도 |
| 지면 충격 안전 높이 | 바닥 위 `2.1m` | 2단 점프 또는 벽 잡기 요구 |
| 체력·데미지 | `12 / 1` | 세 패턴과 2페이즈를 관찰 |

## 패턴 순환

```text
세 능력 미해금
      ↓
 Idle(회색)
      │ 세 능력 + 거리 조건
      ▼
 GroundWave(주황)
      │
      ▼
 AirBurst(청록)
      │
      ▼
 GroundPulse(노랑)
      │
      └────────────→ GroundWave
```

각 패턴은 `AttackWindup → 실행 → AttackRecovery`를 거친다. 피격되면 현재
선딜이 `Hurt`로 취소되며, 플레이어가 사망하면 보스 체력·패턴 순서·투사체가
최초 조우 상태로 복원된다.

### GroundWave

보스 발밑에서 플레이어 방향으로 낮은 직선 투사체 한 발을 보낸다. 단순
점프로 넘을 수 있지만 기둥이나 다른 탄환과 겹치면 2단 점프로 체공 높이를
확보할 수 있다.

### AirBurst

플레이어의 서로 다른 세 높이를 향해 청록색 투사체를 동시에 발사한다. 발사
순간의 위치로 방향이 고정되므로 점프 후 공중 대시로 탄막 궤도를 가로지르는
것이 핵심 대응이다.

### GroundPulse

아레나 바닥 전체를 노란 막대로 예고한 뒤 지면 기준 `2.1m`보다 낮은
플레이어에게 데미지를 준다. 2단 점프로 안전 높이에 도달하거나 아레나 기둥을
벽 잡기·벽 점프로 올라 피할 수 있다. 대시 무적도 공통 `DamageRules`를 통해
존중한다.

## 코드 파편화

| 구성 요소 | 책임 |
|---|---|
| `BossPattern` | 세 패턴 이름 계약 |
| `BossPatternDecisionMath` | 활성 조건, 패턴 순환, 안전 높이, 2페이즈 |
| `AbilityTrialBossController` | 시간, 표현, 투사체, 충격, 피격과 재시작 |
| `PlayerAbilityState` | 세 요구 능력의 단일 보유 상태 |
| `EnemyProjectile` | 지상 파동과 공중 탄막의 이동·충돌 |
| `DamageRules` | 투사체와 지면 충격의 대시 무적 |

```text
PlayerAbilityState ─────────────┐
                               ▼
BossPatternDecisionMath → AbilityTrialBossController
                                  │
                                  ├── EnemyProjectile → Health
                                  ├── GroundPulse ─────→ DamageRules
                                  └── PlayerRespawned → Reset
```

보스 컨트롤러는 능력 ID 문자열을 직접 비교하지 않는다. 빌더가 같은
`AbilityDefinition` 에셋을 플레이어 이동기와 보스에 연결하고,
`PlayerAbilityState.HasAbility`가 관문을 판단한다.

## 구현 방식 비교

| 방식 | 장점 | 단점 | 현재 선택 |
|---|---|---|---|
| enum 순환 상태 머신 | 패턴 순서가 명확하고 테스트가 쉬움 | 복잡한 분기와 병렬 행동에서 switch가 커짐 | 첫 보스 |
| ScriptableObject 패턴 에셋 | 수치·순서 재사용과 디자이너 편집에 유리 | 실행 명령 인터페이스 설계가 추가로 필요 | 패턴 수 증가 시 전환 |
| Behavior Tree | 조건 분기와 우선순위 확장에 강함 | 세 패턴에는 도구 비용이 큼 | 복합 보스에서 비교 |
| Timeline 중심 | 연출과 카메라 동기화가 편함 | 핵심 판정이 연출 에셋에 숨기 쉬움 | 등장·사망 연출에만 검토 |

현재는 첫 보스의 학습 가능한 고정 순서와 포트폴리오 설명 가능성을 우선해 enum
순환 상태 머신을 사용한다. 패턴이 늘어나면 패턴 데이터와 실행 명령을
ScriptableObject로 옮기는 과정을 별도 리팩터링 사례로 기록할 수 있다.

## 시각 예고

| 색 | 패턴 | 표시 형태 |
|---|---|---|
| 주황 | GroundWave | 발목 높이의 짧은 막대 |
| 청록 | AirBurst | 몸 앞의 큰 구체 |
| 노랑 | GroundPulse | 아레나 바닥의 긴 막대 |
| 흰색 | Hurt | 플레이어 공격으로 선딜 중단 |
| 진한 자주 | Recovery | 반격 가능한 후딜 |

체력 절반 이하에서는 몸이 더 밝은 자홍색이 되고 선딜이 `0.68초`로 짧아진다.

## 수동 시연 방법

1. `Main` 씬을 Play하고 2단 점프·공중 대시·벽 잡기를 차례로 획득한다.
2. 확장된 높은 발판 오른쪽 끝에서 독립 `boss_room` 구역으로 이동한다.
3. 지도 `BOSS` 노드가 현재 상태가 되고 카메라가 아레나 전체를 보여 주는
   고정 시점으로 바뀌는지 확인한다.
4. `x=29`의 높은 기둥을 짧아진 벽 점프로 넘어간다.
5. 회색 보스가 자주색으로 활성화되고 주황색 막대를 보이는지 확인한다.
6. 낮은 주황 파동을 점프 또는 2단 점프로 넘는다.
7. 청록색 세 발 탄막을 점프 후 공중 대시로 가로지른다.
8. 긴 노란 바닥 경고가 보이면 2단 점프하거나 기둥에 벽 잡기로 올라간다.
9. 보스 체력을 절반 이하로 낮춰 몸 색과 선딜 속도 변화를 확인한다.
10. 보스를 처치한 뒤 플레이어가 사망하면 보스가 최초 상태로 복원되는지
   확인한다.

## 한계와 다음 단계

- 보스 체력 UI, 아레나 입구 잠금, 등장·사망 연출은 아직 없다.
- 공중 탄막은 동시에 생성되는 고정 세 발이며 시간차 발사 패턴은 없다.
- 보스 처치 ID의 영구 저장은 M6 저장 시스템에서 연결한다.
- 실제 모델·Animator·패턴 VFX·사운드를 추가해야 한다.
- M6에서는 능력·체크포인트·지름길·보스 처치 상태를 저장 데이터로 통합한다.
