# 고정형 원거리 적과 투사체

## 목표

M5의 두 번째 일반 적으로, 이동하며 압박하는 근거리 적과 다른 회피 판단을
요구하는 고정형 원거리 적을 구현한다. 플레이어가 발사 예고를 읽고 점프나
대시로 직선 투사체를 피하도록 만드는 것이 핵심 경험이다.

## 현재 설정

| 항목 | 값 | 의도 |
|---|---:|---|
| 최초 탐지 거리 | `8m` | 높은 발판 진입 전에 충전 표시 노출 |
| 추적 해제 거리 | `9.5m` | 경계에서 공격 상태가 떨리지 않게 함 |
| 허용 높이 차 | `3.8m` | 아래·위 발판을 제한적으로 조준 |
| 공격 선딜 | `0.8초` | 투사체 회피를 준비할 시간 제공 |
| 공격 후딜 | `1.6초` | 연속 탄막 대신 한 발씩 읽게 함 |
| 투사체 속도 | `7m/s` | 점프와 짧은 대시 모두로 회피 가능 |
| 투사체 수명 | `2.5초` | 최대 약 `17.5m` 이동 후 자동 제거 |
| 체력·데미지 | `3 / 1` | 근거리 적과 같은 생존 기준으로 비교 |

원거리 적은 `High_Platform`의 `x=18`에 배치했다. 보라색 캡슐이 적 본체이고,
공격 준비 중 몸 앞에 나타나는 청록색 구체가 발사 원점이다.

## 상태 흐름

```text
대상 없음·8m 밖
        ↓
      Idle
        │ 탐지
        ▼
 AttackWindup 0.8초
        │ 발사 순간 거리·높이 재검사
        ▼
 Projectile 생성
        ↓
 AttackRecovery 1.6초
        └────────→ Idle / AttackWindup

생존 상태 ── 피격 ─→ Hurt
모든 상태 ── 사망 ─→ Dead
플레이어 재시작 ──→ 최초 위치·체력·탄환 초기화
```

한 번 대상을 발견한 뒤에는 `9.5m`까지 인식을 유지한다. 근거리 적과 같은
히스테리시스 원칙을 사용하지만, 이동하지 않는 적이므로 `Chase` 대신 즉시
다음 발사를 준비한다.

## 코드 파편화

| 구성 요소 | 책임 |
|---|---|
| `RangedEnemyDecisionMath` | 거리·높이·인지 이력으로 `Idle` 또는 `AttackWindup` 선택 |
| `RangedEnemyController` | 상태 시간, 시각 예고, 조준, 투사체 생성과 재시작 복원 |
| `EnemyProjectile` | 직선 이동, 수명, 소유자 필터, 데미지와 환경 충돌 |
| `DamageRules` | 플레이어 생존과 대시 무적 공통 판정 |
| `CharacterBodyCollisionPolicy` | 캐릭터 몸은 통과시키고 투사체·환경 반응은 유지 |

```text
RangedEnemyDecisionMath
          ↓
RangedEnemyController ── 생성 ─→ EnemyProjectile
                                      │
                                      ├── DamageRules → Health
                                      └── 환경 Collider → 소멸
```

판단 함수는 `Transform`, `Time`, `Rigidbody`를 알지 않는다. 투사체도 발사
주기와 적 상태를 알지 않으므로 나중에 같은 적이 여러 발 패턴을 사용하거나
다른 적이 같은 투사체를 재사용할 수 있다.

## 투사체 충돌 규칙

- 발사자의 몸과 자식 Collider는 무시한다.
- 목표 플레이어에게만 데미지를 적용한다.
- 다른 적과 훈련용 더미는 통과한다.
- 체크포인트·구역 같은 Trigger는 통과한다.
- 바닥과 벽 같은 일반 환경 Collider에 닿으면 소멸한다.
- 플레이어가 대시 무적이면 데미지 없이 몸을 통과하고 계속 이동한다.
- 한 투사체는 여러 Collider와 겹쳐도 최대 한 번만 해결된다.

발사 방향은 선딜이 끝난 순간의 플레이어 위치로 고정된다. 발사 후에는
플레이어를 따라 휘지 않으므로 예고를 보고 방향을 바꾸거나 점프하는 회피가
가능하다.

## 구현 방식 비교

| 방식 | 장점 | 단점 | 현재 선택 |
|---|---|---|---|
| Trigger + Kinematic Rigidbody | Unity 충돌 이벤트 활용, 환경 반응이 직관적 | 빠른 탄환과 레이어 설정을 주의해야 함 | 현재 프로토타입 |
| SphereCast 직접 이동 | 한 프레임 경로를 직접 검사해 고속 탄환에 강함 | 정렬·필터·이동 코드를 직접 관리 | 고속 투사체에서 검토 |
| 즉시 판정 Raycast | 구현과 비용이 작음 | 화면에서 날아오는 탄환을 피하는 경험이 없음 | 총기·레이저에 적합 |

현재는 회피 가능한 실제 이동체가 필요하므로 Trigger 방식으로 시작했다.
`ContinuousSpeculative` 충돌 모드와 작은 Trigger를 사용한다.

## 수동 시연 방법

1. `Main` 씬을 Play하고 오른쪽 계단을 지나 첫 높은 발판으로 이동한다.
2. 보라색 `RangedEnemy_Sentry`가 진한 자홍색으로 변하고 몸 앞에 청록색 충전
   구체가 나타나는지 확인한다.
3. 발사된 청록색 탄환을 점프하거나 방향을 바꿔 피한다.
4. 충전이 끝나기 직전에 `Left Shift` 대시로 탄환을 통과하고, 탄환이 플레이어
   뒤쪽으로 계속 이동해 벽 또는 수명 만료 때 사라지는지 확인한다.
5. 적 앞을 통과한 뒤 반대편에서도 발사 원점이 플레이어 방향으로 바뀌는지
   확인한다.
6. 적을 처치하거나 탄환이 남은 상태에서 플레이어가 사망하면 적과 탄환이
   초기화되는지 확인한다.

## 한계와 다음 단계

- 현재 투사체는 발사할 때마다 런타임 구체를 생성하므로 다수의 탄막에는
  Prefab과 오브젝트 풀링이 필요하다.
- 시야를 가리는 벽을 발사 전에 검사하지 않아 벽을 향해 쏜 뒤 충돌로
  제거한다.
- 실제 모델·사격 애니메이션·발사와 충돌 VFX·사운드가 필요하다.
- 방향을 잠그고 이동 중 중단되는 세 번째 적은
  [Charge Enemy](ChargeEnemy.md)에 분리해 구현 방식과 회피 판단을 비교한다.
