# 02. 전투 시스템

> `PlayerCombat`은 콤보 입력과 공격 시점을 소유하고,
> `SideScrollerTargeting`·`TargetingMath`는 대상 수집과 선택을 담당하도록
> 분리해 이동을 멈추지 않는 지상·공중 3단 공격을 구현했다.

## 포트폴리오 목표

공격, 이동, 체력, 피격을 서로 결합하지 않고 교체할 수 있는 계약으로
설계한다. 특히 공중 공격과 대시가 수평 이동을 차단하지 않는지 검증한다.

## 해결한 문제와 화면 결과

| 해결하려던 문제 | 적용한 코드 규칙 | 플레이에서 보이는 결과 |
|---|---|---|
| 공격 중 입력이 들어오지 않아 콤보가 끊김 | 현재 공격 중 다음 입력 하나를 버퍼에 보관 | 버튼을 약간 일찍 눌러도 1→2→3타 연결 |
| 공중 공격이 캐릭터를 제자리에 고정함 | 전투는 짧은 수직 완화만 Motor에 요청하고 수평 이동은 소유하지 않음 | 전진·후퇴하면서 공중 공격하고 대시로 취소 가능 |
| 높이가 조금 다른 적에게 정면 공격이 빗나감 | 바라보는 쪽 후보를 NonAlloc으로 모아 각도 제한 안의 최적 대상을 선택 | 낮은 턱이나 작은 높이 차의 적을 향해 판정이 기울어짐 |
| 한 공격이 같은 적에게 여러 프레임 데미지를 줌 | 공격 사이클마다 `HashSet<Health>`로 이미 맞힌 대상 기록 | 한 타당 대상별 데미지 한 번만 적용 |
| 공격 판정과 생존 코드가 직접 결합됨 | `Health`의 공통 데미지 계약만 호출 | 플레이어·더미·일반 적·보스가 같은 피격 흐름 사용 |

## 핵심 코드와 책임

| 코드 | 책임 | 이 코드로 구현한 전투 동작 |
|---|---|---|
| `PlayerCombat.cs` | 입력 버퍼, 콤보 단계, 공격 활성 프레임과 `OverlapBox` 실행 | 3단 지상·공중 공격과 대상별 1회 타격 |
| `CombatMath.cs` | 공격 단계·타이밍에 필요한 순수 계산 | 콤보 경계와 입력 시간의 결정적인 판정 |
| `SideScrollerTargeting.cs` | `OverlapSphereNonAlloc`으로 주변 후보 수집 | 프레임 할당을 줄인 근접 대상 탐색 |
| `TargetingMath.cs` | 방향·거리·높이·깊이 우선순위와 최대 조준 각도 계산 | 바라보는 방향을 보존한 상하 자동 조준 |
| `Health.cs` | 현재 체력, 데미지·회복·사망 이벤트 | 더미와 적이 같은 방식으로 피격·사망 |
| `SideScrollerMotor.cs` | 전투가 요청한 짧은 공중 체공과 계속되는 수평 이동 | 공중 공격 중 이동·대시 연계 |

## 코드에서 공격까지의 흐름

```text
공격 입력
  → PlayerCombat이 현재 콤보 또는 다음 입력 버퍼 결정
  → 활성 프레임에 SideScrollerTargeting이 후보 수집
  → TargetingMath가 현재 바라보는 쪽의 최적 방향 선택
  → Physics.OverlapBox로 공격 범위 조회
  → 아직 맞히지 않은 Health에 데미지 적용
  → 공격·명중 이벤트를 Animator와 Feedback 계층이 표현
```

대상 선택은 캐릭터 방향을 강제로 돌리지 않는다. 입력 방향은 플레이어가
소유하고, 공격 판정만 허용 각도 안에서 보정해 자유로운 이동과 안정적인
근접 판정을 함께 유지한다.

## 현재 구현

- `PlayerCombat`: 입력·공격 타이밍·OverlapBox 판정
- `Health`: 데미지·사망 이벤트
- `TrainingDummy`: 피격 반응과 자동 부활
- 공중 공격의 짧은 수직 속도 완화
- 공격 중에도 수평 이동과 대시 허용
- 3단 기본 공격과 공격 중 다음 입력 버퍼
- 1·2타 기본 데미지, 3타 마무리 보너스
- `ComboStep` 기반 Punch Jab → Punch Cross → Sword Attack 애니메이션
- 바라보는 쪽의 대상만 고르는 횡스크롤 자동 조준
- 높이가 다른 대상을 향해 최대 35도까지 회전하는 공격 판정

## 자동 조준 파편화

| 구성 요소 | 책임 | 분리한 이유 |
|---|---|---|
| `TargetingMath` | 후보 조건·우선순위·각도 제한 계산 | 물리 씬 없이 경계값을 EditMode에서 검증 |
| `SideScrollerTargeting` | `OverlapSphereNonAlloc` 후보 수집 | 물리 탐색 교체가 공격 코드에 번지지 않음 |
| `PlayerCombat` | 선택된 조준 방향으로 히트박스 실행 | 공격 타이밍과 대상 선택 정책을 분리 |

자동 조준은 캐릭터의 방향을 강제로 돌리지 않는다. 공격을 누른 순간 현재 바라보는
쪽만 검색하고, 같은 거리라면 높이·깊이 차이가 작은 대상을 우선한다. 이 방식은
플레이어 입력을 보존하면서 작은 발판 높이 차이 때문에 근접 공격이 빗나가는
문제를 줄인다.

## 구현 방식 비교

| 판정 방식 | 장점 | 단점 |
|---|---|---|
| `Physics.OverlapBox` | 타이밍 제어가 쉽고 테스트하기 좋음 | 애니메이션과 수동 동기화 필요 |
| Trigger Collider | 시각적 범위 확인이 쉬움 | 활성화·중복 피격 관리 필요 |
| Animation Event | 동작과 판정 타이밍이 직관적 | 애니메이션 에셋 의존성이 커짐 |

현재 프로토타입은 `OverlapBox`를 사용하고, 콤보 사이클이 확정되면 공격 데이터를
ScriptableObject로 분리한다.
