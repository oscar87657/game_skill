# 02. 전투 시스템 — 공격은 이동 권한을 어디까지 가져가야 하는가?

> 결론 요약: 현재 프로토타입은 코드 타이머가 공격 시점과 판정을 소유하고,
> 이동 시스템에는 짧은 체공만 요청하는 방식이 자유로운 지상·공중 연계에
> 적합하다. 공격·무기·애니메이션 수가 늘어나면 수치를 Attack Data로 분리하고,
> 정확한 본 궤적이 판정의 핵심이 될 때 Animation Event 또는 Animation 기반
> Hitbox가 더 적합하다.

## 1. 장르에서의 역할

메트로배니아 전투는 탐험 조작 위에 올라간다. 공격을 누를 때마다 캐릭터가
제자리에 고정되면 이동 능력은 전투 선택지가 되지 못하고, 반대로 언제든 모든
행동을 취소할 수 있으면 적의 예고와 공격 리듬이 의미를 잃는다.

- 플레이어 경험: 공격 입력은 짧게 보정되고 3단 콤보로 이어지되, 수평 이동과
  공중 방향 전환은 유지한다.
- 이동 연결: 대시는 공격을 취소하고, 공중 공격은 제한된 체공만 요청한다.
- 적 연결: 플레이어와 적은 `Health`라는 공통 결과 계약을 사용한다.
- 공간 연결: 작은 발판 높이 차이는 제한된 자동 조준으로 보정하지만 뒤쪽 대상은
  자동으로 선택하지 않는다.

핵심은 “자유로운 전투”를 모든 제약의 제거로 정의하지 않는 것이다. 입력 버퍼,
공격 활성 시점, 대시 취소와 조준 각도처럼 예측 가능한 제약을 두되 이동 의도를
불필요하게 빼앗지 않는 것이 목표다.

## 2. 연구 질문과 성공 조건

### 연구 질문

공격의 입력·콤보·판정 타이밍을 코드, Animator, Collider 중 어디에서 소유해야
이동과 자연스럽게 연계되고 애니메이션 교체에도 안정적인가?

### 성공 조건

| 관점 | 성공 조건 |
|---|---|
| 입력 | 현재 공격 중 누른 다음 입력 하나를 `0.24초` 동안 보존한다. |
| 콤보 | 설정된 마지막 단계만 마무리 보너스를 받고 이후 1타로 순환한다. |
| 이동 권한 | 공격은 수평 속도와 바라보는 방향을 직접 쓰지 않는다. |
| 공중 전투 | 한 공격의 체공 요청은 최대 `0.1초`를 넘지 않고 대시가 즉시 취소한다. |
| 타격 | 한 공격은 여러 Collider를 가진 같은 `Health`에 한 번만 데미지를 준다. |
| 조준 | 정면, 거리, 높이, 깊이 조건을 통과한 대상만 최대 `35°`까지 보정한다. |
| 표현 | 공격 시작과 실제 명중은 별도 확정 이벤트로 전달한다. |

## 3. 현재 구현 분석

| 코드 | 책임 | 장르 경험으로 이어지는 결과 |
|---|---|---|
| `PlayerCombat.cs` | 공격 입력 버퍼, 콤보 상태, 타격 지연과 `OverlapBox` 실행 | 이동 중 이어지는 3단 지상·공중 공격 |
| `CombatMath.cs` | 다음 콤보 단계와 설정 길이 기준 마무리 데미지 계산 | 콤보 길이를 바꿔도 마지막 타격의 의미 유지 |
| `SideScrollerTargeting.cs` | `OverlapSphereNonAlloc` 후보 수집과 Health 중복 제거 | 작은 높이 차이를 보정할 대상을 공격 시작 때 선택 |
| `TargetingMath.cs` | 정면·거리·높이·깊이 필터, 점수와 각도 제한 | 캐릭터 방향을 빼앗지 않는 2.5D 조준 보조 |
| `Health.cs` | 체력 제한, 데미지·회복·사망 이벤트 | 더미·일반 적·보스가 같은 결과 계약 사용 |
| `SideScrollerMotor.cs` | 수평 속도 소유와 제한된 공중 체공 요청 적용 | 공격 중 이동 유지, 대시로 공격 취소 |

### 실행 흐름

```text
Attack 입력
  → PlayerCombat이 즉시 시작 또는 다음 입력 하나를 버퍼링
  → StartAttack에서 콤보 단계·타이머·대상 목록 초기화
  → SideScrollerTargeting이 정면 후보 수집
  → TargetingMath가 최적 대상과 제한된 방향 계산
  → hitDelay 뒤 회전된 OverlapBox 한 번 실행
  → HashSet<Health>로 대상별 중복 제거
  → Health가 승인한 데미지만 HitConfirmed 발행
  → Animator·VFX·SFX가 확정 이벤트 표현
```

공격 시작 때 대상을 한 번 고정하고 타격 순간에 다시 탐색하지 않는다. 따라서
짧은 공격 동안 조준선이 흔들리지 않지만, 선딜 중 빠르게 이동한 적을 끝까지
추적하지도 않는다. 현재 근접 공격의 짧은 `0.13초` 지연에는 의도한 절충이다.

### 이동 권한 계약

| 상황 | 전투가 할 수 있는 것 | 전투가 하지 않는 것 |
|---|---|---|
| 지상 공격 | 콤보와 타격 타이머 진행 | 수평 속도 0 고정, 캐릭터 강제 회전 |
| 공중 공격 | Motor에 `0.06초`, 최대 `0.1초` 체공 요청 | 위치 고정, 수평 관성 소유, 중력 영구 중단 |
| 대시 시작 | 현재 공격·버퍼·대상 취소 | 대시 이동과 무적 직접 실행 |
| 명중 | `Health.TakeDamage` 결과에 따라 이벤트 발행 | VFX·SFX 직접 생성 |

이 계약 때문에 제자리 점프 뒤 이동 입력을 새로 넣어도 Motor가 가속을 처리하고,
달리며 공격해도 전투가 이전 수평 속도를 고정하지 않는다.

## 4. 구현 후보 비교

### 타격 시점과 범위 소유 방식

| 후보 | 타이밍·감각 | 제작 반복 | 결합도·테스트 | 비용·위험 | 적합한 상황 |
|---|---|---|---|---|---|
| 코드 타이머 + OverlapBox (현재) | 수치가 결정적이고 즉시 조정 가능 | 모델 없이도 Graybox 반복 가능 | 계산은 테스트 가능, 물리 판정은 통합 테스트 필요 | 애니메이션과 수동 동기화, 조회 배열 할당 | 공격 수가 적고 코드 중심인 프로토타입 |
| Animation Event + Overlap | 시각 프레임과 타격이 직접 맞음 | 클립마다 Event 편집 필요 | 애니메이션 에셋 의존, 누락·중복 Event 추적 필요 | 클립 교체 시 계약 파손 가능 | 최종 애니메이션이 안정되고 본 타이밍이 중요한 게임 |
| 활성 Trigger Hitbox | Scene에서 범위와 지속 구간을 보기 쉬움 | 프리팹·본에 Hitbox 배치 가능 | Enter/Stay 중복과 활성 수명 관리 필요 | Collider 수와 물리 Callback 증가 | 무기 궤적과 다중 활성 프레임이 중요한 액션 |
| Attack Data + 실행기 | 공격별 시간·범위·취소 규칙을 에셋으로 조합 | 디자이너가 코드 없이 변형 가능 | 데이터 검증기와 범용 실행기 필요 | 초기 추상화 비용이 큼 | 무기·스킬·공격 단계가 많이 늘어나는 프로젝트 |

현재 `OverlapBox`는 한 공격에 한 번만 실행하므로 정확한 결과 수를 우선해 할당형
API를 유지한다. 후보 탐색은 공격마다 여러 Collider를 볼 수 있어 고정 24칸
NonAlloc 버퍼를 재사용한다. 대상 밀도가 버퍼 크기를 넘기거나 GC가 실제 예산을
초과하면 결과 잘림과 할당 비용을 함께 측정한 뒤 크기 조정·동적 버퍼·공간 분할을
선택해야 한다.

### 전투 상태 소유 방식

| 후보 | 장점 | 단점 | 선택 조건 |
|---|---|---|---|
| `PlayerCombat` 코드 타이머 (현재) | 입력·쿨다운·타격 순서가 한곳에 있고 디버깅이 빠름 | 공격 종류가 늘면 조건과 SerializeField가 증가 | 기본 3단 공격 하나로 구조를 검증하는 현재 범위 |
| Animator StateMachine 중심 | 전이와 애니메이션 구간을 시각화 | 게임 규칙이 Animator Parameter와 클립에 결합 | 애니메이터가 제작의 중심이고 상태 수가 제한될 때 |
| 데이터 기반 Attack 실행기 | 무기와 스킬을 같은 파이프라인으로 조합 | 취소·파생·조건식을 표현하는 도구가 필요 | 다수 무기와 공격 변형이 실제 요구가 되었을 때 |

### 자동 조준 정책

- 조준 없음: 입력 책임은 가장 명확하지만 작은 Y 차이로 근접 공격이 빗나간다.
- 현재 제한 조준: 정면 의도를 보존하며 Graybox 높이 오차를 완화한다.
- Lock-on: 표적 중심 전투에는 적합하지만 탐험 중 빠른 방향 전환과 다수 적에서
  입력 모드가 복잡해진다.

## 5. 선택과 전환 기준

### 현재 프로젝트에서의 선택

- 선택: 코드 타이머 + 공격 시작 시 제한 자동 조준 + 타격 순간 OverlapBox
- 우선 기준: 이동 자유, 모델 교체 독립성, Graybox에서의 빠른 수치 조정
- 감수한 단점: 공격 모양과 애니메이션이 복잡해질수록 수동 동기화 비용이 커진다.
- 보완: `AttackStarted`와 `HitConfirmed`를 분리하고, 공격 원점을 탐색과 판정이
  공유하며, 조준 계산을 순수 함수로 둔다.

### 다른 방식이 더 나은 경우

- 최종 무기 본의 궤적이 판정 정확도를 결정함: Trigger Hitbox 또는 Animation
  Event 기반 판정을 검토한다.
- 공격·무기·스킬이 10개 이상으로 늘고 같은 필드가 반복됨: Attack Data와 범용
  실행기로 이동한다.
- 차지, 분기 콤보, 지상·공중 파생이 늘어남: Boolean 하나의 입력 버퍼 대신
  timestamp가 있는 Command Buffer와 취소 규칙 표가 필요하다.
- 네트워크 결정론·리플레이가 필요함: Unity 물리 조회와 `Time.deltaTime`을 직접
  소유하는 현재 구조 대신 고정 Tick 전투 시뮬레이션을 사용한다.

구조 전환 신호는 다음과 같다.

1. 공격 하나를 추가할 때 `PlayerCombat`에 네 개 이상의 SerializeField와 분기가
   생긴다.
2. 애니메이션을 바꿀 때마다 타격 지연값을 수동으로 다시 맞춰야 한다.
3. 두 개 이상의 공격 입력, 차지와 방향 파생을 Boolean 버퍼 하나로 구분할 수 없다.
4. Hitbox 모양이 Box 하나로 표현되지 않아 여러 물리 질의를 연속 호출한다.

## 6. 핵심 판단 읽기

### 설정된 마지막 타격만 강화

```csharp
int safeLength = Mathf.Max(1, comboLength);
return safeStep >= safeLength
    ? safeBaseDamage + Mathf.Max(0, finisherBonus)
    : safeBaseDamage;
```

기존에는 마무리 단계가 `3`으로 고정되어 Inspector의 `comboLength 1~5` 계약과
어긋났다. 이제 콤보 길이가 4라면 3타는 기본 데미지, 4타만 보너스를 받는다.
데이터 조정 범위를 열었다면 계산도 같은 값을 기준으로 삼아야 한다.

### 한 공격의 체공 상한

```csharp
return Mathf.Clamp(
    requestedDuration,
    0f,
    Mathf.Max(0f, maximumDuration));
```

공중 공격은 속도를 직접 0으로 만들지 않고 짧은 시간 동안 수직 속도를 0에
가깝게 완화한다. 요청값이 상한보다 커도 반드시 최대값에서 잘라 연속 공격 설정
실수로 장시간 체공하는 문제를 막는다. 새 공격은 타이머를 더하지 않고 다시
설정하므로 각 타격이 짧은 리듬만 만든다.

### 다중 Collider 중복 제거

```text
OverlapBox 결과 순회
  → 부모 Health 조회
  → 자기 자신·null 제외
  → damagedTargets.Add가 처음 성공한 대상만 통과
  → Health가 데미지를 승인하면 HitConfirmed
```

Collider가 아니라 `Health`를 HashSet 키로 사용하므로 머리·몸·무기 Collider가
동시에 들어와도 한 타격으로 계산된다. 부위별 데미지가 필요해지면 이 계약을
Hurtbox와 Damage Receiver로 분리해야 한다.

## 9. 결론

- 자유로운 전투는 공격 상태가 이동 속도를 소유하지 않는 데서 시작한다.
- 입력, 공격 시점, 대상 선택, 데미지 결과와 표현을 나누면 각 정책을 독립적으로
  교체할 수 있다.
- 자동 조준은 방향을 대신 정하는 기능이 아니라 2.5D 공간의 작은 높이 오차를
  보정하는 제한된 접근성 규칙으로 사용한다.
- 데이터 조정 범위와 계산 계약은 반드시 같아야 한다. 가변 콤보 길이와 3타
  하드코딩의 불일치를 이번 분석에서 수정했다.

이 전투 계약은 [13 근거리 적](13-EnemyStateMachine.md)의 예고와 피격,
[14 원거리 적](14-RangedEnemy.md)의 회피 무적,
[16 능력 시험 보스](16-AbilityTrialBoss.md)의 패턴 대응,
[20 플레이어 피드백](20-PlayerFeedback.md)의 확정 이벤트로 이어진다.

## 10. 한계와 다음 실험

- 실제 타격 PlayMode 테스트가 없어 물리 Layer, 회전 Box와 다중 Collider 계약은
  Scene 구성에 의존한다. 독립 전투 Fixture를 만든다.
- `Physics.OverlapBox`는 배열을 할당한다. 공격 빈도와 GC 측정 결과가 예산을
  넘을 때 NonAlloc 또는 재사용 버퍼로 바꾸고 결과 잘림 정책을 함께 정한다.
- 공격 데이터가 `PlayerCombat` SerializeField에 모여 있다. 두 번째 무기 또는
  파생 공격을 추가하기 전에 Attack Definition 최소 실험을 만든다.
- 현재 버퍼는 다음 공격 하나만 기억한다. 방향 파생·차지·스킬이 추가되면 입력
  timestamp와 취소 우선순위를 가진 Command Buffer를 비교한다.
- Hurtbox·경직·넉백·히트 스톱은 아직 공통 계약이 아니다. 먼저 Health 결과와
  표현 이벤트 사이에서 어느 계층이 반응 강도를 소유할지 정한다.
