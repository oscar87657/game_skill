# 플레이어 진행 상태 HUD

## 목표

전투와 탐험에 필요한 체력, 획득한 이동 능력, 로컬 저장 상태를 한 화면에서
확인한다. HUD는 게임 규칙을 직접 계산하지 않고 `Health`,
`PlayerAbilityState`, `GameProgressSaveController`의 공개 이벤트와 API만
사용한다.

## 화면 구성

- 좌측 하단 체력 바와 `현재 / 최대` 수치
- 2단 점프, 공중 대시, 벽 잡기 능력 슬롯
- 명시적인 `SAVE`, `LOAD` 버튼
- `READY`, `SAVED`, `LOADED`, `NO SAVE`, `SAVE FAILED` 결과 문구
- 마우스와 향후 게임패드 UI 입력을 받는 `InputSystemUIInputModule`

능력을 얻기 전에는 슬롯을 `?`로 표시한다. 해금 이벤트를 받으면 슬롯의
이름과 색을 즉시 바꾼다. 체력도 데미지와 회복 이벤트를 받을 때만 갱신하므로
매 프레임 상태를 조회하지 않는다.

## 선택한 구조

```text
Health ───────────────┐
PlayerAbilityState ───┼─ 이벤트 ─ GameProgressHud ─ UI View
                      │
GameProgressSaveController ─ 버튼 호출 ─ JSON 파일
```

- `GameProgressHud`: 상태 구독, 표시 갱신, 저장·불러오기 결과 표현
- `AbilityHudSlot`: 능력 정의와 슬롯 View를 묶는 직렬화 가능한 표현 단위
- `PrototypeSceneBuilder`: HUD 배치와 Input System EventSystem 구성

`GameProgressHud`가 저장 DTO나 파일 경로를 알지 않게 유지했다. 따라서 이후
체크포인트 자동 저장, 여러 세이브 슬롯 또는 클라우드 저장으로 바뀌어도 HUD는
저장 제어기의 성공 여부만 받으면 된다.

## 구현 후보 비교

| 방식 | 장점 | 단점 | 적합한 상황 |
|---|---|---|---|
| `Update`에서 상태 폴링 | 구현이 단순함 | 상태가 안 바뀌어도 매 프레임 UI를 다시 계산함 | 짧은 일회성 프로토타입 |
| 상태 객체가 UI 직접 수정 | 연결 코드가 적음 | 게임 규칙과 화면이 강하게 결합됨 | 교체하지 않을 단일 화면 |
| 이벤트 기반 Presenter | 계산 낭비가 적고 View 교체가 쉬움 | 구독 해제를 관리해야 함 | 확장되는 플레이 HUD |

## 수동 확인

1. `Main` 씬을 실행하고 좌측 하단에 `HP 5 / 5`와 잠긴 세 슬롯이 보이는지
   확인한다.
2. 적이나 투사체에 맞아 체력 수치와 붉은 바가 함께 줄어드는지 확인한다.
3. 이동 능력을 획득할 때 해당 슬롯의 이름과 색이 바뀌는지 확인한다.
4. `SAVE`를 눌러 `SAVED`가 표시되는지 확인한다.
5. 능력이나 위치 진행을 변경하고 `LOAD`를 눌러 저장 시점의 진행이 복원되며
   `LOADED`가 표시되는지 확인한다.
