# 방문 상태 지도 HUD

## 목표

플레이어가 발견한 구역과 현재 위치를 화면 오른쪽 위의 간단한 지도에서 즉시
확인할 수 있게 한다. 지도는 월드 진행 상태를 새로 저장하지 않고
`PlayerWorldState`의 영구 구역 ID와 이벤트를 읽기만 한다.

## 지도 그래프

```text
BACKTRACK SHAFT ── START HALL ── TRAVERSAL LAB ── BOSS ROOM
```

현재 Graybox의 네 구역을 노드 네 개와 연결선 세 개로 표현한다. 이 레이아웃은
실제 거리의 축척보다 구역 간 연결 관계를 전달하는 데 집중한다.

## 구현 후보 비교

| 방식 | 장점 | 단점 | 적합한 상황 |
|---|---|---|---|
| Scene 오브젝트가 방문 상태를 직접 조회 | 구현이 빠름 | 노드마다 진행 로직이 중복되고 테스트가 어려움 | 노드가 한두 개인 일회성 데모 |
| 월드 전체 스크린샷 위에 아이콘 표시 | 실제 지형을 쉽게 이해함 | Graybox 변경 때 이미지를 다시 만들고 미발견 정보가 노출됨 | 완성된 고정형 월드 |
| ID 기반 Presenter + Node/Connection View | 진행 데이터와 표현 분리, 이벤트 기반 갱신, 아트 교체 용이 | 초기 노드와 연결 구성이 필요함 | 구역이 확장되는 메트로배니아 |

이 프로젝트는 세 번째 방식을 선택했다. 지도 UI가 월드 상태를 수정하지 않게
하면 세이브, 스트리밍, 카메라와 같은 시스템이 하나의 상태 소유권을 공유할 수
있다.

## 선택한 구조

```text
WorldZoneVolume
       ↓
PlayerWorldState
  ├─ ZoneVisited
  └─ ZoneEntered
       ↓
WorldMapPresenter
  ├─ WorldMapNodeView
  └─ WorldMapConnectionView
```

- `WorldMapVisualStateMath`: 방문·현재 여부를 `Hidden`, `Visited`, `Current`
  중 하나로 바꾸는 순수 규칙
- `WorldMapPresenter`: 이벤트를 한 번만 구독하고 모든 노드와 연결선을 갱신
- `WorldMapNodeView`: 구역 ID에 대응하는 색상과 레이블 표현
- `WorldMapConnectionView`: 양 끝 구역을 모두 방문했을 때 연결선 공개

매 프레임 상태를 확인하지 않고 `ZoneVisited`와 `ZoneEntered`가 발행될 때만
전체 지도를 다시 그린다. 구역이 네 개인 현재 규모에서는 전체 갱신이 단순하고
안전하며, 이후 노드가 크게 늘면 변경된 구역 주변만 갱신하는 방식으로 바꿀 수
있다.

## 표시 규칙

| 상태 | 표시 | 의미 |
|---|---|---|
| 미방문 | 어두운 노드와 `?` | 아직 발견하지 않은 구역 |
| 방문 | 청록색 노드와 구역 레이블 | 이전에 방문한 구역 |
| 현재 | 주황색 노드와 구역 레이블 | 플레이어가 현재 있는 구역 |
| 연결 발견 | 청록색 연결선 | 양 끝 구역을 모두 방문함 |

현재 상태는 방문 상태보다 우선한다. 첫 Trigger 판정 전에도 `initialZone`을
사용하므로 게임을 시작한 직후 `START` 노드에서 현재 위치를 확인할 수 있다.

## 수동 시연 방법

1. `Main` 씬을 Play한다.
2. 오른쪽 위 `MAP`에서 `START`가 주황색이고 나머지 구역은 `?`인지 확인한다.
3. 이동 실험실로 진입해 `START`는 청록색, `LAB`은 주황색으로 바뀌는지
   확인한다.
4. 백트래킹 샤프트까지 이동해 `SHAFT`가 주황색으로 바뀌고 이전 두 구역은
   방문 상태를 유지하는지 확인한다.
5. 방문한 두 구역 사이의 연결선만 밝게 표시되는지 확인한다.
6. 보스방 입장 뒤 `BOSS` 노드가 현재 상태로 바뀌는지 확인한다.
