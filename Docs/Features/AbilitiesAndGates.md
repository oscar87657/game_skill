# 능력 해금과 게이트

## 목표

메트로배니아의 능력 데이터를 월드 오브젝트나 플레이어 이동 코드에 직접
기록하지 않고, 고유 ID를 가진 정의와 플레이어 보유 상태로 나눈다. 픽업은
해금 요청만 하고 게이트는 보유 여부만 읽도록 구성해 이후 저장·로드와
백트래킹 월드에서도 같은 규칙을 사용한다.

## 범위

- 입력: 플레이어가 `AbilityPickup` Trigger에 접촉
- 상태: `PlayerAbilityState`가 능력 ID를 한 번만 보유
- 출력: 해금 이벤트 발행, 픽업 비활성화, 요구 게이트 개방
- 연결 시스템: 이동 능력, 저장·로드, 월드 게이트, UI

## 구현 후보 비교

| 방식 | 장점 | 단점 | 적합한 상황 |
|---|---|---|---|
| 플레이어 컴포넌트의 `bool` 필드 | 구현이 매우 단순함 | 능력이 늘 때 코드와 저장 형식이 함께 바뀜 | 능력 수가 고정된 작은 프로토타입 |
| `enum`과 비트 플래그 | 조회와 저장이 빠름 | DLC·모드처럼 정의가 늘 때 바이너리 계약 관리 필요 | 능력 목록이 빌드 시 완전히 고정된 게임 |
| ScriptableObject 정의 + ID `HashSet` | 에셋을 픽업·게이트·UI가 공유하고 저장은 ID만 사용 | ID 중복을 제작 단계에서 관리해야 함 | 데이터 중심 진행 시스템과 포트폴리오 비교 |

## 선택한 방식

현재 프로젝트는 ScriptableObject 정의와 ID `HashSet`을 사용한다.
`AbilityDefinition`에는 고유 ID와 표시 데이터만 두고, 획득 여부는
`PlayerAbilityState`에 둔다. ScriptableObject 자체에 `isUnlocked` 같은 값을
저장하면 에셋 하나를 모든 플레이어와 테스트가 공유해 Play Mode 종료 후 상태가
섞일 수 있기 때문이다.

ID 문자열은 이후 세이브 파일이 Unity 오브젝트 참조에 의존하지 않게 한다.
문자열 비교 비용은 능력 수가 적은 이 프로젝트에서 충분히 작으며, 저장 호환성과
Inspector 가독성을 더 중요하게 선택했다.

## 코드 구조

```text
Runtime/
├── AbilityDefinition.cs
├── PlayerAbilityState.cs
├── AbilityPickup.cs
└── AbilityGate.cs

Tests/EditMode/
└── AbilitySystemTests.cs
```

| 구성 요소 | 책임 | 소유하지 않는 것 |
|---|---|---|
| `AbilityDefinition` | ID·표시 이름·설명 | 플레이어 획득 상태 |
| `PlayerAbilityState` | ID 보유·중복 방지·해금 이벤트 | 월드 표현과 충돌 |
| `AbilityPickup` | Trigger 접촉과 획득 표현 제거 | 게이트와 이동 동작 |
| `AbilityGate` | 요구 능력 조회와 통로 충돌 전환 | 능력 지급과 저장 |

게이트는 매 프레임 상태를 검사하지 않고 `AbilityUnlocked` 이벤트를 구독한다.
잘못 구성된 게이트는 통로를 열어 진행 순서를 깨뜨리지 않도록 잠긴 상태를
유지한다.

## Main 씬 진행 루프

```text
시작 지점
  → 지상 대시로 RespawnHazard 통과
  → x=7에서 2단 점프 획득
  → 시작 지점 왼쪽으로 백트래킹
  → Wall_Gate 개방 확인
  → 오른쪽 계단과 높은 발판 등반
  → x=20에서 공중 대시 획득
```

지상 대시는 기본 이동으로 남겨 첫 픽업까지 도달할 수 있게 했다. 2단 점프와
공중 대시는 `SideScrollerMotor`가 매 입력 순간 `PlayerAbilityState`를 조회한다.
요구 에셋이 연결되지 않은 독립 Showcase 씬에서는 기존 기능을 허용해 이전
테스트 씬과의 호환성을 유지한다.

## 수동 시연 방법

1. `Main` 씬을 실행하고 먼저 점프 중 Space를 다시 눌러 2단 점프가 잠겼는지
   확인한다.
2. 공중에서 Shift를 눌러 공중 대시가 시작되지 않는지 확인한다.
3. 오른쪽 `x=7`의 구체를 획득하고 2단 점프가 활성화됐는지 확인한다.
4. 왼쪽으로 돌아가 주황색 `Wall_Gate`의 충돌이 사라졌는지 확인한다.
5. 오른쪽 계단과 높은 발판을 올라 `x=20`의 구체를 획득한다.
6. 점프 후 Shift로 공중 대시가 활성화됐는지 확인한다.
