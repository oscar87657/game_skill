# 근거리 적과 상태 머신

## 목표

M5의 첫 적으로, 플레이어가 가까워지면 추적하고 공격 거리에서 선딜을 보여 준
뒤 데미지를 주는 근거리 적을 구현한다. 이 단계의 핵심은 적 하나를 만드는 데
그치지 않고 판단 규칙을 Unity 실행 코드와 분리해 이후 원거리·돌진 적에서도
비교하고 재사용할 기반을 마련하는 것이다.

## 현재 범위

- 탐지 거리 `6m`, 추적 해제 거리 `8m`
- 공격 거리 `1.25m`, 허용 높이 차 `1.6m`
- 이동 속도 `2.2m/s`
- 공격 선딜 `0.3초`, 후딜 `0.55초`, 데미지 `1`
- 피격 경직 `0.16초`, 체력 `3`
- 대시 무적을 존중하는 공통 데미지 규칙
- X/Y 평면 이동과 생성 시점 Z축 고정
- 발 기준 이동 루트와 중심 기준 캡슐 메시 분리
- 플레이어 재시작 시 최초 위치·체력·상태 복원
- 상태 색상과 공격 결과 구체를 이용한 임시 피드백
- 플레이어·적, 적·적 사이의 몸 충돌 통과

## 상태 흐름

```text
대상 없음·탐지 밖
        ↓
      Idle
        │ 6m 안, 같은 높이
        ▼
      Chase ────── 8m 밖 ─────→ Idle
        │ 1.25m 안
        ▼
 AttackWindup(빨강)
        │ 0.3초 뒤 거리 재검사
        ▼
 AttackRecovery
        │ 0.55초
        └────────────→ Chase / Idle / AttackWindup

모든 생존 상태 ── 피격 ─→ Hurt ─→ 거리 판단
모든 상태 ─────── 사망 ─→ Dead
```

탐지 거리와 추적 해제 거리를 다르게 둔 것을 히스테리시스라고 한다. 두 값이
같으면 플레이어가 경계에 걸쳤을 때 `Idle`과 `Chase`가 프레임마다 바뀔 수
있다. 한 번 발견한 뒤에는 조금 더 먼 `8m`까지 추적하게 해 상태 떨림을 줄였다.

## 코드 파편화

| 구성 요소 | 책임 | 분리한 이유 |
|---|---|---|
| `EnemyState` | 상태 이름 계약 | 문자열 오타를 막고 테스트 결과를 명확히 표현 |
| `EnemyDecisionMath` | 거리·높이·탐지 이력으로 다음 상태 계산 | 물리 씬과 프레임 없이 경계값 검증 |
| `MeleeEnemyController` | 상태 시간, 이동, 공격, 피격과 시각 피드백 실행 | Unity 생명주기와 도메인 판단의 경계 유지 |
| `DamageRules` | 생존·양수 데미지·무적 공통 검사 | 환경 위험과 적 공격의 규칙 중복 방지 |
| `Health` | 현재·최대 체력과 이벤트 | 플레이어와 적이 같은 생존 계약 사용 |

의존 방향은 다음처럼 한쪽으로만 흐른다.

```text
MeleeEnemyController
    ├── EnemyDecisionMath
    ├── DamageRules ──→ Health
    ├── CharacterController
    └── PlayerRespawnController.Respawned

DamageVolume ─────────→ DamageRules ──→ Health
```

`EnemyDecisionMath`는 `Transform`, `CharacterController`, `Time`을 알지 않는다.
따라서 “탐지 밖”, “공격 경계”, “다른 높이”, “사망 상태 고정”을 EditMode에서
빠르게 검사할 수 있다.

## 구현 방식 비교

| 방식 | 장점 | 단점 | 현재 판단 |
|---|---|---|---|
| enum + C# 상태 머신 | 흐름과 중단 우선순위가 명확하고 단위 테스트가 쉬움 | 상태 수가 매우 많아지면 switch가 커짐 | 일반 적의 작은 행동 집합에 적합 |
| Animator 상태 머신 중심 | 애니메이션 전환을 시각적으로 편집하기 쉬움 | 게임 판단이 애니메이션 에셋에 숨기 쉬움 | 추후 표현 계층으로만 사용 |
| Behavior Tree | 복잡한 보스 패턴과 우선순위 확장에 유리 | 첫 일반 적에는 도구와 구조 비용이 큼 | 보스 단계에서 다시 비교 |

현재는 enum 상태 머신을 선택했다. 판단은 순수 함수로, 실행은 MonoBehaviour로
분리한다. 실제 모델이 들어오면 Animator는 상태를 표현하지만 탐지와 공격 성공
여부를 결정하지 않게 한다.

## 공격 판정에서 중요한 선택

공격 범위는 선딜을 시작할 때 한 번, 실제 타격 순간에 다시 한 번 확인한다.
두 번째 검사가 없다면 플레이어가 빨간 선딜을 보고 대시로 빠져나가도 공격을
맞게 된다. 실제 데미지는 `DamageRules`를 거쳐 대시 무적 중인 플레이어에게
적용되지 않는다.

실제 공격 이펙트가 들어오기 전에는 적 앞의 작은 구체로 판정을 확인한다.

| 표시 색 | 의미 |
|---|---|
| 빨강 | 공격 선딜 진행 중 |
| 노랑 | 공격 적중 |
| 청록 | 대시 무적으로 방어 |
| 회색 | 선딜 중 범위를 벗어나 빗나감 |

## 배치 기준과 재시작

`MeleeEnemy_Grunt` 루트의 Y 좌표는 발 위치다. 캡슐 메시를
`MeleeEnemy_Visual` 자식으로 분리하고 중심을 `Y=0.9`에 배치해 메시의 바닥과
`CharacterController`의 바닥이 일치한다. 모델을 교체하더라도 이동 루트는
발 기준을 유지한다.

적은 `PlayerRespawnController.Respawned` 이벤트를 구독한다. 플레이어 재시작이
완료되면 적의 생존 여부와 상관없이 최초 위치, 최대 체력, `Idle` 상태,
충돌체와 렌더러를 함께 복원한다. 체크포인트의 단순 체력 회복 이벤트에는
반응하지 않으므로 회복만으로 전투가 초기화되지는 않는다.

## 캐릭터 몸 충돌 정책

캐릭터가 서로 밀거나 적 여러 마리가 겹쳐 길을 막는 문제는 전용 물리 레이어로
분리했다.

| 레이어 | 번호 | 대상 |
|---|---:|---|
| `PlayerBody` | `6` | 플레이어 루트 `CharacterController` |
| `EnemyBody` | `7` | 적 루트와 훈련용 더미의 몸 Collider |
| `Default` | `0` | 바닥, 벽, 경사, Trigger와 일반 월드 |

`CharacterBodyCollisionPolicy`는 첫 Scene이 로드되기 전에 다음 두 조합만
무시한다.

```text
PlayerBody ↔ EnemyBody : 통과
EnemyBody  ↔ EnemyBody : 통과
PlayerBody ↔ Default   : 충돌 유지
EnemyBody  ↔ Default   : 충돌 유지
```

`Physics.IgnoreCollision`을 적마다 반복 호출하는 대신 레이어 규칙을 사용하므로
런타임에 적이 늘어나도 새 Collider 쌍 목록을 만들 필요가 없다. 플레이어 공격은
`Physics.OverlapBox`, 자동 조준은 `Physics.OverlapSphereNonAlloc` 조회를
사용하므로 몸 충돌을 꺼도 `EnemyBody`의 `Health`를 계속 찾을 수 있다.

추후 Trigger 방식 Hitbox/Hurtbox를 추가할 때는 몸 루트에 두지 않고 별도의
전투 판정 레이어를 가진 자식으로 구성한다. 그러면 몸은 통과하면서 공격
Trigger만 서로 반응하게 만들 수 있다.

## 수동 시연 방법

1. `Main` 씬을 Play한다.
2. 오른쪽 계단의 `MeleeEnemy_Grunt` 캡슐에 접근한다.
3. 탐지되면 주황색에서 노란색으로 바뀌며 따라오는지 확인한다.
4. 가까이 서서 빨간 공격 구체 뒤 노란 적중 구체가 나타나는지 확인한다.
5. 빨간 구체가 나타난 순간 `Left Shift` 대시로 통과해 청록색 무적 판정
   구체가 나타나는지 확인한다.
6. 기본 공격을 세 번 맞혀 흰색 피격 표시와 사망 시 비활성화를 확인한다.
7. 적에게 피해를 주거나 처치한 뒤 플레이어가 사망하면, 적이 계단 위 최초
   위치와 체력으로 복원되는지 확인한다.

## 한계와 다음 단계

- 임시 캡슐·색상·판정 구체를 실제 모델·Animator·공격 VFX로 교체해야 한다.
- 낭떠러지 감지와 순찰 범위가 없어 현재는 배치한 발판을 벗어날 수 있다.
- 공격은 단일 거리 검사이며 별도 Hitbox/Hurtbox와 넉백이 없다.
- 원거리 적과 투사체는 [Ranged Enemy](RangedEnemy.md)에 분리해 공통 계약과
  다른 공격 판단을 비교한다.
- 방향을 잠그고 이동 중 중단되는 세 번째 적은
  [Charge Enemy](ChargeEnemy.md)에 분리해 구현 방식과 회피 판단을 비교한다.
