# J01 — 같은 발판에서 점프 제어와 애니메이션을 어떻게 선택할까?

상태: **실행 준비 완료**. Unity 임포트, EditMode 174개, JumpLab PlayMode, macOS 빌드와 앱 시작 화면을 확인했다. 아래 적합성은 가설이며 사용자 플레이 결론이 아니다.

## 질문과 사전 예측

- 고정 탄도는 동일한 점프를 반복하기 쉽지만 낮은 천장 아래의 높이 조절은 제한적일 것이다.
- 해제 제어는 짧은 발판에 유리할 수 있지만 같은 Space 입력도 유지 시간에 따라 결과가 달라질 것이다.
- 시간 곡선은 정점 시간을 직접 조절하기 쉽지만 천장 접촉·낮은 바닥으로의 낙하에서 별도 중단 규칙이 필요할 것이다.
- 고정 시간 애니메이션은 B의 짧은 점프나 천장 접촉에서 실제 상승·하강과 어긋날 수 있다.

이 예측을 실행 결과로 수정하는 것이 목표다. 어느 후보도 기본 정답으로 정하지 않는다.

## 조사 출발점

[출처 노트](../SOURCES.md)의 개발자 물리 설명·공개 플레이어 코드·Unity 이동·Root Motion 문서를 읽는다.
현재 후보는 해당 게임의 복제 코드가 아니다. 원문에서 읽은 구조와 우리 실행 조건을 따로 기록한다.

## 실행 후보와 흐름

모든 후보는 `JumpExperiment`의 동일 입력 → 수직 이동량 → `CharacterController.Move` → 실제 충돌 → 계측·Animator 흐름을 따른다.

| 후보 | 코드 | 핵심 판단 | 가설상 적용 조건 |
|---|---|---|---|
| A 고정 탄도 | `Assets/Experiments/JumpLab/GravityJump.cs` | 초기 속도 이후 일정 중력의 평균 속도로 적분 | 반복 가능한 높이와 체공 시간이 필요한 경우 |
| B 해제 제어 | `Assets/Experiments/JumpLab/ReleaseCutJump.cs` | 버튼을 놓으면 상승 속도 상한 적용, 이후 A와 같은 적분 | 짧은 점프와 긴 점프를 같은 버튼으로 구분할 경우 |
| C 시간 곡선 | `Assets/Experiments/JumpLab/TimedCurveJump.cs` | 곡선의 두 시점 높이 차이를 충돌 이동량으로 전달 | 정점 시점을 직접 조정하고 싶은 경우 |

B가 A의 적분을 재사용하는 것은 의도적이다. 다르게 비교하는 부분은 해제 규칙이며 중력 계산을 억지로 다르게 쓰지 않는다.
C도 절대 위치를 덮어쓰지 않는다. 천장 접촉 시 곡선을 중단하고, 곡선 종료 아래의 바닥으로는 일반 중력 낙하한다.

## 고정한 조건

- Unity `6000.5.5f1`, 3D CharacterController, X/Y 이동, 정면 Orthographic 카메라.
- 키보드 A/D·방향키와 Space, 게임패드 왼쪽 스틱·South 버튼.
- 가로 속도 5m/s, 캡슐 높이 1.7m, 반지름 0.3m.
- A/B 중력 24m/s², 초기 속도 12m/s → 이론상 높이 3m, 원래 높이 복귀까지 1초.
- B 해제 상승 속도 상한 2m/s.
- C 높이 3m, 길이 1초, 기본 정점 정규화 시간 0.4. 정점 시점은 A/B의 0.5초와 다르다.
- 코요테 타임·점프 버퍼·추가 점프·공격·세이브는 현재 실험에 없다.
- 충돌·접지 프레임·skin width 때문에 표시 값은 이론값과 소폭 다를 수 있다.

## 실행

`Assets/Experiments/JumpLab/JumpLab.unity`만 열고 Play한다.
`Game Skill > Experiments > Create Jump Lab`은 없는 씬을 생성하거나 기존 씬을 연다. 기존 편집 씬을 닫지 않고 Play 시작 씬을 JumpLab으로 지정한다.
Main을 다시 Play하려면 Unity의 Play 시작 씬 설정을 해제한다. 메뉴의 `Use Current Scene for Play`로 해제할 수 있다.

1. 가운데 평지에서 `1 → R` 후 Space를 짧게 누르고 놓는다. 같은 위치에서 길게 누른다.
2. `2`, `3`에서도 반복한다. 입력 유지 시간과 마지막 높이·체공 시간·착지 거리를 기록한다.
3. 왼쪽 x=-7의 천장 아래로 이동해 점프한다. 모든 후보가 천장을 통과하지 않고 상승을 중단해야 한다.
4. 오른쪽 높이 0.8m, 2m, 3.5m 발판을 오른다. 이 높이는 발판 꼭대기 기준이다.
5. `F`로 애니메이션 전환 기준만 바꿔 동일한 동작을 반복한다.
6. Play 중 `JumpLab Player` Inspector에서 한 수치만 바꿔 다시 측정한다. Play 중 변경은 저장되지 않으므로 노트에 남긴다.

`1/2/3`은 속도·위치·기록을 초기화한다. `R`도 지난 기록을 지우므로 먼저 적는다.
화면 높이는 이륙 위치 기준, 거리는 수평 변위의 절댓값, 체공 시간은 실제 착지 프레임까지다.
입력 유지 시간은 첫 버튼 해제 또는 착지까지다. 수동 입력은 프레임 단위로 측정되며 정밀 리플레이가 아니다.

## 애니메이션

기존 CC0 Quaternius Humanoid 모델과 `HumanoidPlayer.controller`를 재사용한다.
`Jump_Start`와 `Jump_Loop`의 공중 전환을 실제 수직 속도 또는 고정 0.5초 기준으로 비교한다.
두 방식 모두 실제 접지 시 지상 상태로 복귀한다. Root Motion은 꺼져 있다.
이는 **같은 클립의 연결 방식 비교**이며 다른 아트 스타일·착지 클립·Root Motion 적합성 검증을 완료한 것은 아니다.

관찰할 것: 상승을 일찍 끊었을 때 자세, 천장 접촉 직후 낙하 전환, 발판 착지의 접지와 발 미끄러짐.
후속 실험에서는 별도 착지 클립과 다른 길이의 도약 클립을 선정해 비교한다.

## 조건 변경과 장르 적용 — 다음 단계

- 먼저 실제 비교를 한 뒤, 입력 버퍼 또는 코요테 타임 하나를 추가하고 착지 실패가 어떻게 달라지는지 본다.
- 획득 전 목표 노출→이동 능력 획득→같은 방의 새 경로→지름길 귀환 구간을 만든다.
- 능력 없이 정밀 점프로 우회할 수 있는 경로를 허용할지 결정한다.
- 새 요구에서 어떤 후보를 선택할지 먼저 적고 구현·플레이 결과로 수정한다.

현재는 이런 판단을 시작할 준비 단계다. 조건부 최종 결론은 아직 없다.
