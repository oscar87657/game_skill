# 조사와 비교 실험 방법

## 시작은 문제와 예측

“점프 구현” 대신 “낮은 천장 아래에서 짧게 뛰면서 높은 발판에도 도달하려면?”처럼 쓴다.
후보별 예상 결과를 플레이 전에 기록한다. 현재 코드가 이겨야 할 이유는 없다.

## 조사

- 개발자 발표·회고: 해결하려던 게임 조건과 감수한 비용을 찾는다.
- 공개 소스: 실제 제어 흐름, 버전·커밋, 엔진 의존성과 라이선스를 확인한다.
- 엔진 문서: API가 보장하는 동작과 직접 처리해야 할 부분을 구분한다.
- 튜토리얼·커뮤니티: 후보와 실패 사례 탐색에 사용하고 핵심 주장은 원문과 실행으로 확인한다.
- 게임 관찰: 입력과 화면 결과만 기록한다. 비공개 코드를 알아낸 것처럼 쓰지 않는다.

[출처 노트](SOURCES.md)에 읽은 범위·핵심 판단·실험 질문을 남긴다. 링크 수를 조사 성과로 세지 않는다.
공개되어 있다는 이유로 복사 가능하다고 판단하지 않는다. 원문 설명을 참고한 자체 구현과 가져온 코드를 구분한다.

## 비교 축을 섞지 않기

- **이동량 생성**: 속도·중력, 시간 곡선, 애니메이션 Root Motion.
- **충돌 실행**: CharacterController, Rigidbody, 직접 cast.
- **입력 규칙**: 즉시 실행, 버퍼, 코요테 타임, 해제 제어.
- **애니메이션 연결**: 실제 상태 기반, 고정 시간, 이벤트 기반.

서로 다른 축은 조합될 수 있다. J01은 충돌을 CharacterController로 고정하고 수직 이동량 생성과 해제 제어를 비교한다.
Rigidbody와 Root Motion을 같은 선택지 목록의 경쟁자로 놓지 않는다.

## 통제 조건

후보마다 출발 위치, 캐릭터 크기, 가로 속도, 지형, 카메라, 입력 장치, 프레임 조건을 같게 한다.
탭은 목표 유지 시간과 실제 유지 시간을 기록한다. 수동 플레이의 입력은 완벽히 같지 않으므로 반복하고 편차를 남긴다.
최대 높이·시간을 맞춘 비교와 자유 튜닝 비교를 구분한다. 곡선 방식의 정점 시점까지 같다고 가정하지 않는다.

## 애니메이션 실험

처음에는 같은 클립으로 연결 방식만 바꾼다. 다음에는 연결 방식을 고정하고 클립을 교체한다.
발 미끄러짐, 상승·낙하 전환, 천장 충돌 후 자세, 착지 시 접지, 취소 반응을 관찰한다.
“잘 어울림”은 구체적 장면과 지연·어긋남·수정 비용으로 설명한다.

## 증거 구분

| 표시 | 의미 |
|---|---|
| 출처 확인 | 원문에 실제로 명시된 내용 |
| 코드 확인 | 저장소 구현을 읽고 확인한 동작 |
| 자동 검증 | 해당 테스트와 조건에서 통과한 계약 |
| 관찰 | 입력·환경·횟수를 남긴 실제 플레이 결과 |
| 가설 | 아직 실험하지 않은 예상 |

자동 테스트는 재미와 손맛의 증거가 아니다. 캡처 한 장은 안정성의 증거가 아니다.
결론에는 적용 조건, 실패 조건, 다른 방식으로 바꿀 신호를 함께 적는다.

## 학습의 마지막 단계

다른 높이의 발판, 더 긴 클립, 이동 발판, 피격 같은 새 조건을 하나 적용한다.
기존 선택을 유지할지 바꿀지 먼저 예상하고 수정해 본다. 이후 능력 획득과 재방문이 있는 작은 공간에서 검증한다.
