# 메트로배니아 경험 기준

이 문서는 완성 게임의 콘텐츠 명세가 아니라 구현 대안을 평가하는 플레이 경험의
기준이다. 코드 구조가 달라도 아래 경험을 더 안정적이고 설명 가능하게 만들면
유효한 대안으로 본다.

## 한 문장 정의

3D 공간을 측면 시점으로 탐험하고, 이동 능력을 획득해 과거 장소의 의미와
이동·전투 선택지를 함께 바꾸는 2.5D 액션 메트로배니아.

## 참고 방향

`ENDER MAGNOLIA: Bloom in the Mist`에서 다음 원칙을 관찰한다.

- 빠르고 명확한 좌우 이동과 점프
- 수평 진행과 수직 탐색이 교차하는 동선
- 전투와 탐험에서 함께 쓰이는 이동 능력
- 체크포인트와 지름길이 줄여 주는 반복 비용
- 전경, 플레이 레인과 배경이 만드는 깊이감
- 공격 전 예고와 회피 뒤 반격 기회의 가독성

참고작의 코드, 캐릭터, 세계관, 맵 구조와 시각 표현은 복제하지 않는다. 화면에서
관찰할 수 있는 장르 원칙만 독립적인 코드와 Graybox로 검증한다.

## 핵심 경험 가설

### 1. 이동은 탐험의 언어다

기본 이동은 즉각적이고 예측 가능해야 한다. 새 능력은 같은 공간에서 도달 가능한
거리·높이·경로를 분명히 바꿔야 하며, 획득 전에도 잠긴 가능성을 관찰할 수 있어야
한다.

검증 질문:

- 입력 보정이 실수를 줄이면서 조작의 책임감은 유지하는가?
- 대시·2단 점프·벽 이동의 범위가 레벨 수치로 예측 가능한가?
- 여러 공중 행동이 자유롭게 연결되지만 무한 이동은 막히는가?

### 2. 능력은 열쇠보다 동사에 가깝다

능력은 특정 문을 여는 Boolean에 그치지 않는다. 탐험 경로, 전투 회피와 공격
기회, 과거 장소를 보는 관점을 함께 바꿔야 한다.

검증 질문:

- 한 능력이 최소 두 가지 플레이 맥락에서 의미가 있는가?
- 게이트가 능력 이름이 아니라 플레이 행동을 시험하는가?
- 보스와 적이 능력 사용을 강제하지 않고 유리한 선택으로 만드는가?

### 3. 백트래킹은 지식의 변화다

같은 장소로 돌아와도 플레이어의 능력, 열린 지름길, 지도 정보와 목표가 달라야
한다. 반복 이동 시간보다 “이제 저곳에 갈 수 있다”는 기억 회수가 중요하다.

검증 질문:

- 능력 획득 전에 미래 경로나 보상을 발견할 수 있는가?
- 귀환 경로는 지름길로 짧아지는가?
- 보상이 이동 비용과 기억 부담에 비례하는가?

### 4. 실패는 진행 이해를 깨뜨리지 않는다

사망 뒤 플레이어는 마지막 기준점과 유지된 영구 진행을 이해할 수 있어야 한다.
체크포인트, 부활, 저장은 서로 다른 수명의 상태를 일관되게 복구해야 한다.

검증 질문:

- 사망 시 잃는 것과 유지되는 것이 예측 가능한가?
- 부활 뒤 적·플레이어·카메라가 같은 실행 기준점으로 돌아오는가?
- 앱을 종료해도 능력·구역·지름길·보상이 복원되는가?

### 5. 공간과 위험은 화면으로 읽힌다

카메라, 지도, 조명, 적 예고와 피드백은 설명 문장 없이 다음 이동과 회피 시점을
판단하게 해야 한다.

검증 질문:

- 구역 경계에서도 캐릭터가 화면에서 사라지지 않는가?
- 2.5D 원근이 진행 평면을 혼동시키지 않으면서 깊이를 보여주는가?
- 공격 판정 전 예고와 판정 후 피드백이 구분되는가?

## 통합 플레이 루프

```text
새 구역 탐색
  → 아직 사용할 수 없는 경로와 위험 기억
  → 전투·체크포인트로 안전 구간 확보
  → 이동 능력 획득
  → 전투와 이동 선택지 변화
  → 지름길을 열어 이전 구역으로 복귀
  → 기억한 경로에서 보상과 새 연결 발견
  → 다음 능력을 시험하는 조우 진입
```

## Reference Implementation 범위

| 축 | 현재 검증 사례 |
|---|---|
| 기본 동작 | 가속 이동, 점프, 대시·달리기, 근거리 공격 |
| 이동 능력 | 2단 점프, 공중 대시, 벽 잡기·벽 점프 |
| 월드 | 시작 홀, 실험실, 백트래킹 샤프트, 보스 방 |
| 진행 | 능력 게이트, 지름길, 최대 체력 보상, 지도 방문 상태 |
| 생존 | 체력, 무적, 체크포인트, 사망과 부활 |
| 조우 | 근거리, 원거리, 돌진 적과 능력 시험 보스 |
| 영구 상태 | 능력, 체크포인트, 방문 구역, 지름길, 보상, 보스 |

이 수량은 출시 콘텐츠 목표가 아니라 비교 연구를 위한 최소 사례다. 같은 질문을
반복하는 적·구역·아이템은 추가하지 않는다.

## 월드 설계 기준

- 실제 이동은 X/Y 평면에 한정하고 Z축은 전경·배경과 원근 표현에 사용한다.
- 구역은 한 방향 선형 연결만 갖지 않고 지름길 또는 순환 경로를 포함한다.
- 다음 능력이 필요한 장소를 획득 전에 한 번 보여준다.
- 체크포인트 주변에서 다음 목표나 귀환 경로 중 하나를 읽을 수 있게 한다.
- 구역 입구는 색, 형태, 조명, 카메라 구도로 구분한다.
- 백트래킹 보상은 영구 강화, 선택 조우, 새 정보 중 하나를 제공한다.
- 카메라 소유권과 플레이어 구역 판정이 어긋날 때 플레이어 가시성을 우선한다.

## 진행 상태 분류

| 수명 | 예시 | 기본 처리 |
|---|---|---|
| 한 프레임·행동 | 입력 버퍼, 대시 시간, 공격 단계 | Controller가 갱신 |
| 한 생명 | 현재 체력, 적 전투 상태, 일시적 투사체 | 부활 시 복구 또는 재생성 |
| 한 플레이 세션 | 현재 Scene 로드 상태, Pause | 실행 중에만 유지 |
| 영구 진행 | 능력, 체크포인트, 구역, 지름길, 보상, 보스 | ID 기반 저장 |

일반 적의 생존 여부와 일시적인 물리 오브젝트는 기본적으로 저장하지 않는다.
이 원칙을 바꾸는 콘텐츠가 생기면 저장 크기보다 플레이어 기대와 부활 규칙을
먼저 다시 정의한다.

## 평가하지 않는 범위

- 세계관과 장편 서사
- 최종 캐릭터·환경 아트 품질
- 다수 무기와 대규모 스킬 트리
- 절차 생성 월드
- 멀티플레이
- 모바일·콘솔 출시 최적화

이 항목은 현재 시스템 비교의 결론을 바꿀 구체적인 요구가 생기기 전까지 연구
범위에 넣지 않는다.
