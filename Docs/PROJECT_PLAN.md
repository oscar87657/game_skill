# 학습 계획 — 구현 선택을 연습하는 실험실

## 방향 전환

2026-09-21부터 `01 → 23` 기능 문서 개편 순서를 중단한다. 기존 게임을 더 완성하거나 현재 코드를 정당화하는 것이 목표가 아니다.
외부 자료를 읽고 다른 구현을 직접 실행한 뒤, 새로운 조건에서 선택하고 수정하는 능력을 훈련한다.
이전 산출물은 [Reference Index](REFERENCE_INDEX.md)에 남긴다.

## 한 학습 단위

1. 플레이 문제와 예상 결과를 먼저 적는다.
2. 개발자 원문·공개 코드·엔진 문서에서 다른 접근을 조사한다. 출처와 사용 조건을 확인한다.
3. 차이가 의미 있는 후보를 최소 두 개 직접 실행 가능하게 만든다. 코드가 왜 달라지는지 설명한다.
4. 같은 입력·공간·캐릭터 조건으로 비교하고 실패 사례를 기록한다.
5. 애니메이션 결합 방식을 바꾸고, 시각적 자연스러움과 조작 응답의 충돌을 확인한다.
6. 요구사항 하나를 바꿔 수정 범위와 새 오류를 확인한다.
7. 짧은 메트로배니아 탐험 구간에 적용해 능력·게이트·재방문의 영향을 본다.
8. 어떤 상황에서 어느 방식을 사용할지 증거와 한계를 붙여 설명한다.

## 순서

| 단계 | 질문 | 실행할 비교 | 완료 조건 |
|---|---|---|---|
| 준비 | 같은 조건에서 반복할 수 있는가? | 독립 JumpLab, 세 후보, 계측·초기화, 조사 노트 | 씬 생성·컴파일·계약 테스트와 실행 점검 |
| J01 | 점프 높이와 착지를 얼마나 제어할 것인가? | 고정 탄도 / 해제 시 상승 속도 제한 / 시간 곡선 | 탭·홀드·천장·발판 비교, 애니메이션 차이, 조건부 결론 |
| J02 | 이동량과 충돌은 누가 결정하는가? | CharacterController / Rigidbody 기반 / 필요 시 cast 기반 | 경사·이동 발판·넉백 중 같은 실패 사례 재현과 비교 |
| C01 | 공격 판정과 애니메이션 시점을 누가 소유하는가? | 코드 시간 / Animation Event / 궤적 질의 | 클립 교체·재생 속도 변경·취소·벽 앞 공격 비교 |
| W01 | 능력은 어떻게 장소를 다시 읽게 만드는가? | 명시적 잠금 / 이동 거리·높이 게이트 | 획득 전 관찰→획득→재방문, 우회와 지름길 실험 |
| R01 | 사망 뒤 무엇을 복원하는가? | Scene 재로드 / 선택적 상태 복구 | 적·수집물·체크포인트·영구 진행의 차이 확인 |

표의 후보는 출발 가설이다. 조사 결과 더 적합한 구분이 나오면 바꾼다. 모든 실험의 코드를 미리 만들지 않는다.

## 준비와 연구 완료 구분

- **준비됨**: 실행 후보와 비교 조건이 있고 최소 자동 검증이 가능하다.
- **비교 중**: 원문 조사와 사용자 플레이 관찰을 쌓는 중이다.
- **조건 변경 검증됨**: 새 요구를 적용하고 처음 선택의 한계를 확인했다.
- **학습 완료**: 조사 근거, 실행 차이, 애니메이션 적합성, 장르 구간 결과, 조건부 선택을 설명할 수 있다.

문서 작성·GIF 생성·테스트 통과만으로 학습 완료 처리하지 않는다.

## J01 다음 순서

- 같은 위치에서 A/B/C를 탭·홀드해 첫 예상을 검증한다.
- 원문 코드를 읽고 이 실험이 원문과 무엇이 다른지 기록한다.
- 같은 클립에서 상태 기반 전환과 고정 시간 전환을 비교한다.
- 다른 도약·착지 클립을 선정하고 실제 접지 타이밍을 비교한다.
- 입력 버퍼 또는 코요테 타임을 한 번에 하나씩 추가해 난이도와 실수 허용을 관찰한다.
- 획득 전에는 보이기만 하고 획득 후 도달할 수 있는 방을 만든다. 현재 발판 실험실은 이 단계 완료를 대신하지 않는다.

## 작업 범위

기존 Main·촬영 재질·복구 파일은 보존한다. 실험은 별도 씬과 Assembly에서 진행한다.
로컬 검증과 변경 검토를 마친 단위로 커밋한다. 푸시·릴리스는 사용자가 요청한 때 진행한다.
