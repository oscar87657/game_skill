# game_skill 프로젝트 계획서

## 1. 프로젝트 개요

### 목적

Unity의 주요 게임 개발 기능을 작은 예제로 직접 구현하고, 구현 과정과 결과를
GitHub에 지속적으로 기록한다. 최종적으로 여러 예제를 결합한 짧은 플레이
데모를 완성한다.

### 완료 상태의 모습

- 저장소를 복제한 뒤 문서만 보고 프로젝트를 실행할 수 있다.
- 각 기능은 독립적으로 확인 가능한 Scene 또는 테스트를 가진다.
- 핵심 로직에는 최소 한 개 이상의 EditMode 또는 PlayMode 테스트가 있다.
- README에 기능 목록, 실행 방법, 스크린샷 또는 GIF가 정리되어 있다.
- PC용 데모 빌드가 GitHub Release에 등록되어 있다.

## 2. 범위

### 포함

- 3D 플레이어 이동과 카메라
- 오브젝트 상호작용
- 체력, 데미지, 전투
- 아이템과 인벤토리
- 적 AI와 상태 머신
- UI, 사운드, 세이브/로드
- 테스트, 문서, 데모 빌드

### 초기 범위에서 제외

- 멀티플레이 네트워크
- 백엔드 및 계정 시스템
- 모바일 스토어 출시
- 대규모 오픈 월드
- 유료 에셋 의존 기능

새 기능은 핵심 일정이 끝난 뒤 별도 마일스톤으로 추가한다.

## 3. 개발 원칙

1. 기능 하나를 작은 Scene 하나에서 검증한다.
2. 데이터와 동작을 분리하고, 설정 데이터에는 ScriptableObject를 활용한다.
3. Scene 간 직접 참조와 전역 Singleton 사용을 최소화한다.
4. Inspector에 노출되는 값에는 의미와 범위를 알 수 있는 이름을 사용한다.
5. 기능 완료 시 코드, 테스트, 문서, 시각 자료를 함께 갱신한다.

## 6. Git 작업 방식

### 브랜치

```text
main
feature/player-movement
feature/interaction
feature/inventory
fix/jump-ground-check
docs/inventory-guide
```

`main`은 실행 가능한 상태를 유지한다. 기능 브랜치는 한 가지 목적에 집중하고
완료 후 `main`에 병합한다.

### 커밋 접두어

| 접두어 | 용도 |
| --- | --- |
| `feat` | 새로운 기능 |
| `fix` | 버그 수정 |
| `refactor` | 동작 변경 없는 구조 개선 |
| `test` | 테스트 추가 또는 변경 |
| `docs` | 문서 변경 |
| `chore` | 설정과 유지보수 |

### 버전

- `v0.1.0`: 첫 번째 플레이 가능한 통합 데모
- 이후 기능 추가는 minor, 버그 수정은 patch 버전을 올린다.
