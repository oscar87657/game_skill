# 학습 결과의 공개와 정리

최우선은 메트로배니아 이해도와 구현 선택 능력이다. 포트폴리오는 학습 결과를 정리한 부산물이다.
기능 수, 문서 수, 커밋 수를 진도로 삼지 않는다.

## 남길 결과

- 읽은 출처와 이해한 실행 흐름
- 같은 문제를 해결하는 서로 다른 실행 코드
- 동일 조건의 비교와 실패 장면
- 애니메이션·입력·레벨 조건을 바꿨을 때의 수정
- 작은 탐험 구간에서의 효과
- 어떤 요구에서 어느 방식을 선택할지에 대한 조건부 결론

## 기록과 Git

연구 질문 하나의 코드·검증·노트를 함께 검토할 수 있게 변경을 묶는다.
기존 촬영 Material·복구 파일은 실험 변경과 섞지 않는다. `git add .` 대신 경로를 명시한다.
문서 하나 작성했다고 자동 커밋·푸시하거나 공개 완료로 표시하지 않는다.
로컬 검증 후 커밋하고, 원격 푸시와 릴리스는 사용자 요청에 맞춘다.

## 영상

새 실험은 `J01-후보-조건`처럼 실험 ID를 사용한다. 과거 `01`~`23` 번호는 유지한다.
실험 영상에는 후보·튜닝·입력 조건을 남긴다. 보기 좋은 성공 장면뿐 아니라 실패와 어긋남도 보존한다.
