# 포트폴리오 운영 계획

이 저장소는 하나의 2.5D 메트로배니아를 완성하면서, 게임 기능을 작은 문제로
분해하고 구현 방식의 선택 근거를 기록하는 기술 포트폴리오다.

## 운영 원칙

- 하나의 `Main` 씬은 통합 플레이를 담당한다.
- `CaptureStudio` 씬은 이동·전투·적·보스 기능을 넓은 구역에서 빠르게
  재현하고, 진행 흐름이 필요한 기능은 `Main`에서 촬영한다.
- 기능마다 코드, 테스트, 문서, 시연 자료를 한 묶음으로 남긴다.
- 구현 방식이 두 가지 이상이면 최소 하나의 대안을 문서로 비교한다.
- 최종 선택은 성능보다 현재 프로젝트의 요구사항과 유지보수성을 기준으로 설명한다.

## 문서 서술 원칙

기능 문서는 알파벳순이 아니라 실제 구현 순서의 `01 → 23` 번호를 사용한다.
독자는 완성 결과만 보는 것이 아니라, 앞 단계에서 만든 계약을 다음 기능이
어떻게 재사용했는지 따라갈 수 있어야 한다.

```text
플레이 문제
  → 선택한 코드 구조
  → 핵심 판단과 실행 흐름
  → Unity에서 보이는 동작
  → 자동 테스트
  → GIF·스크린샷 증거
```

- 제목 다음에는 “어떤 코드로 어떤 동작을 구현했는가”를 한 문장으로 쓴다.
- 핵심 코드 표에는 클래스의 책임과 화면 결과를 함께 적는다.
- 코드 조각은 문법 소개가 아니라 중요한 상태 판단이나 의존 분리를 설명한다.
- GIF 설명은 조작 키 나열보다 해당 결과를 만든 코드 규칙을 설명한다.
- 대안 비교에는 다른 프로젝트 규모에서 그 대안이 더 적합한 경우도 기록한다.

## 기능 단위 완료 기준

1. 입력과 출력이 정의되어 있다.
2. 런타임 책임이 작은 컴포넌트로 분리되어 있다.
3. 정상·경계·실패 케이스 테스트가 있다.
4. `CaptureStudio` 또는 `Main`에서 기능을 재현할 수 있다.
5. README에 연결할 짧은 GIF 또는 스크린샷이 있다.
6. 핵심 코드와 화면 결과의 연결이 설명되어 있다.
7. 선택한 구현 방식과 대안의 트레이드오프가 문서화되어 있다.

## 단계

### Phase 1 — 이동 포트폴리오

- 입력 추상화
- 가속 이동과 점프
- 코요테 타임·점프 버퍼
- 더블점프
- 지상·공중 대시
- 대시 속도 곡선
- 카메라 추적

### Phase 2 — 전투 포트폴리오

- 공격 상태와 쿨다운
- Hitbox·Hurtbox
- Health와 Damage 계약
- 피격·무적·사망
- 공중 공격과 캔슬
- 콤보 사이클
- 히트 스톱과 피드백

### Phase 3 — 월드 시스템

- 상호작용
- 체크포인트
- 능력 획득과 게이트
- 백트래킹 보상
- 저장·불러오기

### Phase 4 — AI와 공개 정리

- 적 상태 머신
- 보스 패턴
- 기능별 GIF·다이어그램
- 전체 아키텍처 문서
- GitHub Release와 플레이 영상
